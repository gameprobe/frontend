# UI12 — Claude 진단: 프로필/전적 페이지가 전적검색 서비스처럼 보이지 않는 이유

> 역할: 제품/UX/정보구조 관점의 비판과 개선 방향 제안. **구현 아님, 제품 코드 미수정.**
> 기준: `docs/ui-design-guardrails.md`, `docs/ui-reference-audit.md`.
> 대상 구조(현재 HEAD 기준): `PlayerProfile.tsx`(오케스트레이터) + `PlayerHeaderCard`
> + `ProfileFilterBar` + `profile-dashboard-grid`(사이드바 8패널 + 메인: overview-stack
> 3카드 → 최근 경기).
>
> **v2 보강(self-check 반영)**: 자기검증(`ui12-claude-self-check.md`, 결론 REVISE)
> 에서 지적한 빈틈을 보강했다. 추가/수정: (a) §2-bis "VALORANT 경기 문맥 점검" 절
> 신설(요원·역할·맵·라운드·공/수·스파이크·교전을 현재 데이터 가능 vs 신규로 분류),
> (b) §5에 경기 상세(스코어보드·라운드) 재배치 골격 추가, (c) 공/수 side·라운드
> endType 승패 사유를 **§7(승인 후)에서 §6(신청 전 가능)로 상향**, (d) "전적분석"
> 입장과 검색→프로필 진입 흐름을 §6에 명문화. §1~§8 골격과 번호는 유지.

## 0. 한 줄 요약

지금 페이지는 **"요약 카드 모음"**이지 **"전적검색 서비스"**가 아니다. 전적 사이트의
주인공인 **경기 리스트**가 화면에서 5번째 요소로 밀려 있고, 같은 시즌 통계가
**헤더·사이드바·메인에 2~3번 중복**되며, **Mock 배지가 8곳 이상 반복**돼 "운영
서비스"가 아니라 "데모"로 읽힌다.

---

## 1. 현재 페이지가 보기 불편한 핵심 이유 5개

1. **동일 데이터 2~3중 중복.** 시즌 승률/KD/HS%/ACS가 `PlayerHeaderCard`의 KPI
   그리드(L40-49)와 메인의 `SeasonSummaryCard`에 **두 번**, Career Peak가 헤더
   rank-context(L105-109)와 사이드바 "전체 시즌 최고 기록"(L67-88)에 **두 번**,
   이전 시즌이 헤더(L110-118)와 사이드바 "이전 시즌 티어"(L90-110)에 **두 번**,
   최근 20판 WR/KAST가 헤더 form(L121-125)과 `RecentTwentySummaryCard`에 **두 번**
   나온다. 사용자는 같은 숫자를 반복해서 읽으며 "정보가 많다"가 아니라 "정돈이
   안 됐다"고 느낀다.

2. **헤더 카드 과적재(overload).** `PlayerHeaderCard` 하나가 정체성 + KPI 4종 +
   현재 티어 + Career Peak + Previous + 최근 폼 + Preview Score 배지를 전부 담는다.
   **시선이 멈출 1차 초점이 없다.** 전적 사이트 헤더는 "아바타·이름·티어·갱신"
   정도로 압축돼 있고 나머지는 아래로 분산된다.

3. **본체(경기 리스트)가 묻혀 있다.** 읽기 순서가 헤더(거대) → 필터 →
   `profile-overview-stack`(SeasonSummary + RankHistory + RecentTwenty 3카드) →
   그제서야 최근 경기다. 전적검색의 핵심 행동("이 사람 최근 어땠나")을 보려면
   요약 카드 3개를 지나쳐 스크롤해야 한다.

4. **배지·고지 노이즈.** `Mock / Preview`, 패널마다 `Mock`, 섹션 헤더 `Mock Data`,
   사이드바 disclaimer까지 같은 의미의 배지가 8곳 이상 반복된다. 정직성은 좋지만
   **반복이 시각적 잡음**이 되어 신뢰도를 오히려 떨어뜨린다.

5. **위계 없는 평면 나열.** 사이드바가 8개 패널을 **모두 같은 무게**로 쌓고
   (career peak·이전 시즌·정확도·역할·무기·맵·활동 시간대·팀원), 메인도 요약
   카드와 경기 리스트가 비슷한 비중이라 **무엇이 중요한지** 화면이 말해주지 않는다.

---

## 2. 전적검색 서비스처럼 보이지 않는 이유

- **전적 사이트의 IA 원칙은 "검색 → 한 줄 요약 → 경기 리스트가 화면을 지배"**인데,
  현재는 요약 카드가 화면을 지배하고 경기 리스트가 부차적이다.
- **경기 행의 스캔 리듬이 없다.** 한 행(`match-card`)에 결과 strip + outcome(결과/
  스코어/시간) + 모드/무기 + 요원/맵 + 핵심 pill 3 + 보조 pill 5 + 하이라이트 태그
  + Preview Score 배지 + 양팀 요원 아이콘 10개 + 펼침 화살표가 동시에 들어간다.
  열 그룹이 ~9개라 "승패 → 요원 → KDA → 핵심지표"의 빠른 시선 이동이 안 된다.
  OP.GG 행이 스캔되는 이유는 **노출 지표를 결과·요원·KDA·핵심 2~3개로 제한**하기
  때문이다.
- **헤더가 "프로필 명함"이 아니라 "대시보드 위젯 묶음"**처럼 보인다. 전적 서비스
  헤더는 정체성과 현재 상태(티어·갱신)만 강조한다.
- **"갱신/마지막 업데이트" 같은 운영 신호가 없다.** 전적 사이트의 신뢰감은 "방금
  갱신됨" 표시에서 크게 온다(단, 신규 데이터 필요 — §7 참고).
- **모든 칸이 카드 + Mock 배지**라, 실데이터를 다루는 서비스가 아니라 컴포넌트
  쇼케이스로 읽힌다.

## 2-bis. VALORANT 경기 문맥 점검 (현재 데이터 가능 vs 신규 필요)

> self-check에서 가장 약했던 부분. 전적검색을 넘어 **전적분석**으로 보이려면
> "집계 숫자(ACS/ADR/KAST…)"뿐 아니라 **경기의 전투 서사**(라운드·공/수·스파이크·
> 교전)가 화면에 읽혀야 한다. 각 요소를 현재 Mock 스키마 기준으로 분류한다.

| VALORANT 요소 | 현재 데이터 | 신청 전 가능? | 비고 |
|----------------|-------------|---------------|------|
| 요원(Agent) | `agentId`(요약·참가자), 실 PNG 3/10 | 부분 가능 | 행/스코어보드 요원 표시는 가능, 누락 이미지는 자산 게이트(UI9B) |
| 역할군(Role) | `roleWinRates.role`(듀얼/이니시/센티넬/컨트롤러 라벨) | 가능 | 역할 승률 표시 가능. 아이콘은 자산 게이트(UI9D). 헤더 요원과 역할 맥락 연결은 라벨로 가능 |
| 맵(Map) | `mapId`/`mapWinRates`, 실 PNG 3개 | 가능 | 맵별 성적·행 맵 표기 가능. 누락 맵 이미지는 자산 게이트 |
| 라운드(Round) | `MatchRound.endType`, `scoreAfterRound{attackers,defenders}` | **가능(상향)** | 라운드 승패·**종료 사유(endType)**·점수 진행은 기존 데이터로 표현 가능 |
| 공격/수비(Side) | `scoreAfterRound.attackers/defenders` | **가능(상향)** | 전반/후반 공·수 구간 표시 가능. 그동안 누락됐던 핵심 빈틈 |
| 스파이크(Spike) | endType에 결과 사유 내포(설치/해체 여부 라벨화 가능 범위) | 부분 | endType 라벨로 "스파이크 폭발/해체" 수준은 가능. **타임라인상 설치/해체 시각·플랜터**는 신규 Mock(UI9C) |
| 교전(첫 킬/트레이드/멀티킬) | 없음 | 불가 | 라운드 이벤트 필드 없음 → 신규 Mock(UI9C) |
| ACS / ADR / KAST / HS% / DDΔ/R | 존재(`CombatStats`·`MatchInsight`) | 가능 | 이미 표시 중. 중복 제거·위계만 손보면 됨 |
| 무기/정확도 | `topWeapons`, 전체 `accuracy{head,body,legs}` | 가능 | 표시 가능. **무기별** 적중 분포는 없음 → 신규 Mock |

핵심 시정: **공격/수비 side와 라운드 종료 사유(endType)는 기존 데이터로 표현
가능한데도 v1 진단이 §7(승인 후)로 미뤘다.** 이 둘은 "VALORANT 경기처럼 읽히게"
만드는 저비용·고효과 항목이므로 §6(신청 전)로 옮긴다.

## 3. 줄이거나 제거해야 할 요소 (기존 데이터만으로 가능)

- **메인 `profile-overview-stack` 축소.** `SeasonSummaryCard`는 헤더 KPI와 중복 →
  제거하거나 헤더로 흡수. `RecentTwentySummaryCard`도 헤더 form과 중복 → 한 곳만
  유지. `RankHistoryChart`는 남기되 **메인 본문이 아니라 슬림 스트립/사이드 보조**로.
- **헤더 분해.** 헤더는 정체성 + 현재 티어 + 핵심 1줄(승률·KD·HS%·최근폼)까지만.
  Career Peak/Previous는 헤더에서 빼고 사이드바 "랭크" 블록 한 곳으로 통합.
- **Mock 배지 단일화.** 패널마다 붙은 `Mock`/`Mock Data`/`Mock / Preview`를 제거하고
  **헤더 근처 전역 고지 1개**로 통합.
- **사이드바 패널 수 축소/병합.** 8개 → 핵심 4~5개. "활동 시간대", "자주 함께한
  팀원"은 후순위로 내리거나 접기. "전체 시즌 최고 기록"+"이전 시즌 티어"+현재 티어는
  하나의 **랭크 카드**로 병합(중복 제거).
- **경기 행 슬림화.** 보조 pill 5개(ADR·KAST·DDΔ/R·HS%·티어)는 기본 숨김 →
  펼침에서. 행 기본은 결과·요원·맵·KDA·ACS + 핵심 1~2개. 양팀 요원 10아이콘은
  과밀 → 축약하거나 펼침으로. 행별 Preview Score 배지는 축소.

## 4. 위로 올려야 할 정보

1. **경기 리스트(최근 경기)** — 전적 서비스의 주인공. 헤더+필터 **바로 아래
   메인 컬럼의 시각적 hero**로 올린다.
2. **현재 티어 + 시즌 승률·KD·HS% 한 줄** — 헤더에 압축된 단일 headline로(중복
   카드 대신).
3. **승패 신호** — 경기 행에서 가장 강한 시각 요소(결과 컬러 바/배경)로.
4. **필터(큐/시즌/기간)** — 경기 리스트 바로 위에 붙여 "리스트를 거르는 도구"임을
   명확히(현재는 헤더와 그리드 사이에 떠 있음).

## 5. 전체 페이지 재배치 제안 (정보 구조 재설계)

> OP.GG/Tracker의 **정보 구조만** 참고. 디자인 복제 아님. 기존 데이터/에셋만으로
> 달성 가능한 골격.

```
┌───────────────────────────────────────────────────────────┐
│ [A] 압축 헤더 밴드 (1줄~2줄)                                  │
│   아바타 · RiotID#tag · Lv/region · 현재 티어+RR ·            │
│   headline: 승률 · K/D · HS% · 최근폼 WR  · (전역 Mock 고지 1개)│
├───────────────────────────────────────────────────────────┤
│ [B] 필터 바 (큐 · 시즌 · 기간) — 리스트 바로 위              │
├──────────────────┬────────────────────────────────────────┤
│ [C] 좌측 레일     │ [D] 메인 = 최근 경기 리스트 (HERO)        │
│ (좁게)            │                                          │
│  · 랭크 요약      │  날짜 그룹 → 경기 행(승패 강조·요원·KDA·   │
│    (현재+피크+    │   핵심지표) → 펼침 상세                    │
│     이전 통합)    │                                          │
│  · 역할 승률      │  (선택) RankHistory 슬림 스트립을         │
│  · 맵 성적        │   리스트 상단 또는 레일에 보조 배치        │
│  · 무기/정확도    │                                          │
│  · (접기) 활동/팀원│                                          │
└──────────────────┴────────────────────────────────────────┘
```

핵심 원칙:
- **메인 컬럼 = 경기 리스트**가 화면의 60~70%를 차지하는 hero.
- **요약은 중복 제거 후 한 번만**: headline은 헤더, 상세 분포는 사이드바, 추세는
  RankHistory 한 곳.
- **사이드바는 우선순위 정렬**: 랭크 > 역할/맵/무기/정확도 > (접기) 활동/팀원.
- **Mock 고지는 전역 1개**, 카드별 배지 제거.

### 5-bis. 경기 상세(펼침/매치 상세)의 VALORANT 골격

> 전적**분석**의 본체는 매치 상세다. 프로필 IA와 동급으로 다룬다. 모두 기존
> 데이터(`MatchDetail.participants`, `MatchRound.endType`, `scoreAfterRound`)로
> 가능한 골격이며, 이벤트/경제 등 없는 데이터는 신규 Mock 게이트로 둔다.

```
[펼침/매치 상세]
  ① 매치 헤더: 맵 · 모드 · 최종 스코어 · 결과 · 길이
  ② 라운드 타임라인(UI8B 보존) + 공/수 구간 표시 + 라운드별 endType(종료 사유)
  ③ 팀별 스코어보드: 팀 구분 헤더 · 자기 행 하이라이트 · 기존 컬럼(요원·KDA·ACS·
     ADR·HS%) 정렬
  ④ (게이트) 첫 킬/스파이크 설치·해체 시각/경제 → 신규 Mock(UI9C) 후
```

핵심: ①~③은 기존 데이터로 신청 전 가능. 특히 **②의 공/수 구간 + endType**가
"이 화면은 VALORANT 경기를 이해하고 있다"는 인상을 만든다.

## 6. API 신청 전 반드시 고칠 것 (신규 데이터/자산 불필요 · 최우선)

1. **경기 리스트를 hero로 승격** — `profile-overview-stack`을 경기 리스트 위에서
   걷어내거나(요약 카드 축소/사이드 이동) 리스트를 상단으로. (`PlayerProfile.tsx`
   순서·`profile-dashboard-grid` 비율, CSS/JSX 재배치)
2. **시즌 통계 중복 제거** — 승률/KD/HS%/Career Peak/이전 시즌/최근20을 **한
   곳에서만**. 헤더 headline + 사이드바 랭크 카드로 정리, 메인 중복 카드 제거.
3. **헤더 압축** — 정체성 + 티어 + headline 1줄. Career Peak/Previous는 사이드바로.
4. **Mock 배지 단일화** — 전역 고지 1개로. 카드별 `Mock`/`Mock Data` 제거.
5. **경기 행 스캔 리듬 정리** — 기본 노출(결과·요원·맵·KDA·ACS) / 보조 지표는
   펼침. 양팀 10아이콘·행별 점수 배지 정리.
6. **사이드바 위계화** — 핵심 4~5패널 우선, 저가치 패널 접기/하단.
7. **필터를 리스트 컨텍스트로** — 필터 바를 경기 리스트 헤더에 붙임.
8. **(신규·상향) 라운드 공/수 구간 + 종료 사유 표시** — 매치 상세 타임라인에서
   `scoreAfterRound.attackers/defenders`로 전·후반 공/수 구간을, `endType`으로
   라운드 종료 사유(제압/스파이크/해체/시간초과 라벨)를 표현. **신규 Mock 불필요.**
   v1에서 §7로 잘못 미뤘던 항목.
9. **(신규) "분석처럼 읽히는" 기존 데이터 구성** — 역할/맵/정확도/최근 폼을 단순
   카드 나열이 아니라 "이 플레이어는 X 역할·Y 맵에 강하다" 식 강점/약점 요약으로
   묶기. 통계 비교(평균 대비)는 보류하되, **있는 데이터로 분석적 읽기**는 가능.
10. **(신규) 검색→프로필 진입 흐름 점검** — 전적"검색" 서비스의 첫 인상인 검색
    입력→로딩→결과(또는 빈/오류) 상태가 일관되게 읽히는지 확인(홈→프로필 연결).

> 위 10개는 모두 **기존 Mock 데이터·기존 에셋·CSS/JSX 재배치**로 가능하다(가드레일
> "데이터 없는 UI 금지" 위반 없음). 특히 8~9는 "전적**분석** 서비스"로 보이게 하는
> 저비용 항목이다. UI11 기존 Task에 갇히지 말고 **레이아웃 골격 재설계(UI12)**
> 관점으로 묶어 처리할 것을 권장한다.
>
> 정직성 기준선: Mock 배지를 줄이되(§6-4), "이 데이터는 예시"라는 **전역 고지 1개**는
> 유지한다. 줄이는 것은 *반복*이지 *고지 자체*가 아니다.

## 7. API 승인 후로 미룰 것 (신규 데이터/자산/실연동 필요)

- **"마지막 갱신 시각 + 갱신 버튼"** — 실 fetch/timestamp 필요(실 API/RSO).
  지금 넣으면 가짜 신호 → 보류.
- **요원 집계 카드(모스트/탑 요원·요원별 승률·KD)** — `ProfileSidebarStats`에 필드
  없음. 신규 Mock 또는 실 API(승인 후).
- **스코어보드 요원 이미지 10요원 완성** — 신규 자산(UI9B).
- **라운드 첫 킬/스파이크 설치·해체 시각/플랜터/클러치/멀티킬/경제** — 라운드
  이벤트 필드 없음 → 신규 Mock(UI9C). (단 endType 기반 "종료 사유"와 공/수 구간은
  §6-8로 신청 전 가능 — 혼동 주의.)
- **역할군 아이콘, 무기별 Head/Body/Legs 분포** — 신규 자산/Mock(UI9D).
- **평균 대비 비교·통계 기반 분석 코멘트(수치 비교)** — 기준 통계 표본(Phase 5).
  (단 §6-9의 "있는 데이터로 강점/약점 읽기"는 신청 전 가능 — 수치 비교가 아님.)
- **GameProbe 고유 차별화(Score 심화, 코칭 등)** — API 승인 후 강화.
