## What I May Have Misunderstood

| 가능 오해 | 실제 | 자기 판정 |
|-----------|------|-----------|
| “보기 불편함 = 디자인 미흡” | 사용자는 **전적검색 서비스 완성도**를 말함 | 대부분 맞게 봤으나 §2.5(Arial·eyebrow)는 취향 비중이 약간 큼 |
| “UI11 실패” | UI11은 **Task 범위 내** 마감, **목표(서비스 인상)** 미달 | 원문은 이 구분을 했으나, 독자가 “UI11 잘못”으로 읽을 여지 있음 — 의도적 |
| “OP.GG 복제” | 정보 구조만 | 원문은 준수. 다만 레퍼런스 대비 gap을 **영역별 표**로 안 쓴 것은 audit 재활용 부족 |
| “모든 Mock 고지가 나쁨” | 정직한 고지는 가드레일 | 원문 §7에서 원칙 유지·면적만 축소로 균형 맞춤 — 사용자 의도와 일치 |

**확인하지 않은 전제**

- 실제 브라우저 viewport에서 above-the-fold를 **측정하지 않았다**. 논리적 순서 기반
  추론이며, 헤더·차트 높이에 따라 “경기가 완전히 안 보임” 정도는 기기마다 다를 수 있다.
- UI11G 이후 **런타임 스크린샷 없이** 코드·문서만으로 평가했다.

### Strictness 상세

**너무 보수적일 수 있는 부분**

- **M6 (요원 placeholder 70%)**: Riot API **신청용 스크린샷** 목표라면 **BLOCKER

**너무 강했을 수 있는 부분**

- **B1 above-the-fold**: 논리적으로 맞으나, 일부 viewport에서는 “경기 일부 노출”
  가능 — “1차 시선·스크롤 비용”으로 완화 표현 여지.
- **RankHistoryChart 무거움**: VAL Tracker도 랭크 추이를 쓰므로, “LoL식 rank graph
  과잉”과 구분해 쓰지 않은 점은 재검토 필요.

**적절했던 부분**

- B2 (미동작 필터): API 심사 **기능 허위** — BLOCKER 타당.
- M5 (Preview Score 반복): 신청 전 **비표준 지표 주인공화** — MAJOR 타당.

## Missing Criticism

원문에 **넣었어야 하나 빠진** 비판:

1. **공격/수비(side) 라벨 부재** — `MatchRoundsTab` disclaimer; VAL 라운드 읽기의 필수 축.
2. **역할군 아이콘 없음** — 텍스트 role win rate만으로는 Tracker/OP.GG VAL 프로필과
   거리가 큼.
3. **큐/게임 모드 필터 부재** — Preview filter는 있으나 Competitive/Unrated 등 VAL
   맥락 없음; LoL “전체/솔랭” 필터 기대와도 어긋남.
4. **헤더 요원 정체성 약함** — 대형 요원 아트/최근 요원 없이 KPI 카드만 → **에이전트
   슈터** 정체성 약함.
5. **LoL식 프로필 오해** — Career Peak + Previous Season + RankHistoryChart + 좌측
   장문 sidebar = **LoL 랭크 대시보드**에 가까운 정보 밀도; VAL은 **경기·요원·맵** 중심.
6. **지표는 많은데 읽히지 않음** — ACS/ADR/KAST/DDΔ/R/HS% **데이터는 VAL 표준에
   가깝게 갖춤**; 문제는 “부족”이 아니라 **한 행에 전부 노출**이라는 점을 더 분명히.
7. **스파이크** — round chip에 “폭발/해제”는 있으나 plant/defuse **이벤트·타임라인**
   없음을 VALORANT 분석 서비스 gap으로 명시하지 않음.
8. **API 신청 전 필수 vs 승인 후** — 한 표로 정리하지 않아 §6·§8·§10이 분산.

## Recommended Revision

`ui12-cursor-review.md` **수정 시 추가·강화 권장** (우선순위):

1. **§ 신규: VALORANT 도메인 gap** — 공격/수비, 스파이크 이벤트, 역할군 아이콘,
   큐/모드, 요원 정체성(헤더·모스트 요원).
2. **§ 신규: LoL식 오해 위험** — rank history·career peak·sidebar stack vs VAL
   **경기·요원·맵 우선** 대비.
3. **§ 신규: API 신청 전 / 승인 후 매트릭스**

   | 신청 전 (Must) | 승인 후 (Defer) |
   |----------------|-----------------|
   | 경기 리스트 1순위 IA | GameProbe Preview Score 본격 노출 |
   | 필터 제거/실동작/축소 | Phase 5 기준 통계 분석 |
   | 경기 행 스캔 압축 | 라운드 이벤트 Mock(UI9C) |
   | KPI 중복 제거 | 실 API 갱신·RSO |
   | 맵 PNG 리스트 적용(H10) | 요원 7종(UI9B) — **신청 전 Must vs Defer는 H9 사람 결정** |
   | Mock/Preview 면적 축소 | 무기 Head/Body/Legs 필드 확장 |

4. **심각도 조정 검토** — M6 → API 신청 목표 시 **BLOCKER 후보** 명시; 공/수 side
   **MAJOR** 추가.
5. **§5 보강** — “지표 부족”이 아닌 **“VAL 표준 지표의 스캔 순서·접기 실패”**.
6. **audit § 영역별 1줄 gap** — 프로필 상단·리스트·스코어보드·라운드·성과/분석을
   표로 요약 (디자인 복제 없이).

- Verdict `CHANGES_REQUIRED` + `HUMAN_DECISION_REQUIRED`
