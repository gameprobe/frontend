# UI Reference Audit — GameProbe vs Tracker.gg / OP.GG식 정보 구조

## 목적

UI9A까지의 수정이 의도한 방향(전적 사이트식 정보 구조)에 맞는지 확신하기
어렵다. 이 문서는 **현재 GameProbe**와 **Tracker.gg / valorant.op.gg식 정보
구조 패턴**을 영역별로 비교해, **무엇을 가져오고 / 가져오지 않고 / 어떤 순서로
수정할지**를 결정하기 위한 근거를 모은다.

이 문서는 **계획·검토용 문서**이며, 제품 코드 변경이 아니다. 실제 작업 순서
확정은 사람/GPT 검토 후에 한다.

## 원칙

- 레퍼런스는 **정보 구조·배치 원칙·읽기 흐름만 참고**한다. 디자인(색/타이포/
  그래픽/배지)·레이아웃을 **복제하지 않는다**. (가드레일: `ui-design-guardrails.md`)
- **데이터가 없는 UI는 만들지 않는다.** 현재 Mock에 없는 지표/이벤트를 보여주기
  위해 임의 값을 생성하지 않는다.
- 신규 외부 자산·신규 Mock은 **사람 결정(PENDING-DECISION)** 사안이며, 이 문서는
  그 결정을 **선결정하지 않고 후보로만** 기록한다.

## 현재 GameProbe 구조 근거 (조사 기준점)

- 프로필(`/players/[puuid]`) 2열: `clamp(280px,24vw,320px)` + `minmax(0,1fr)`,
  콘텐츠 최대 폭 1320px(UI9A), 상단 헤더 → 필터 → 좌측 보조 / 중앙 메인 흐름.
- 컴포넌트: `PlayerHeaderCard`, `ProfileSidebar`, `SeasonSummaryCard`,
  `RankHistoryChart`, `RecentTwentySummaryCard`, `MatchSummaryList`,
  `MatchDetailPanel` + `MatchTabs` + `Match{Scoreboard,Rounds,Performance,Analysis}Tab`.
- 데이터/에셋 한계: 요원 실 PNG 3/10(스코어보드 7명 placeholder), 역할군 아이콘
  없음, 무기 Head/Body/Legs 필드 없음, `MatchRound`에 첫 킬/스파이크/클러치 등
  이벤트 필드 없음, 라운드 공/수 side 라벨 미표시, 분석 탭은 Mock Preview 예시
  점수(72/68/—/61).

> 위 한계는 UI9B(요원 자산)·UI9C(라운드 이벤트 Mock)·UI9D(역할/무기 시각화)와
> 직접 연결된다. 이 audit의 목적은 그 셋의 **착수가 아니라 우선순위 재정렬**이다.

## 종합 — 작업 순서 재정렬 후보 (초안, 사람/GPT 확정 전)

> 아래는 **제안**일 뿐 확정이 아니다. UI9B/UI9C/UI9D는 여전히 PENDING-DECISION.

1. **배포 버전 표시(낮은 난이도·자산/Mock 불필요)** — 먼저 처리해 이후 모든 UI
   변경의 배포 반영을 화면에서 검증할 수 있게 한다. → **TASK-015UI10A**.
2. **데이터/에셋 불필요한 정보 구조 보정** — 최근 경기 리스트 승패 강조, 헤더 KPI
   요약, 스코어보드 팀 구분/자기 하이라이트 등 기존 데이터로 가능한 항목.
3. **에셋 필요(요원 7종·역할 아이콘)** — UI9B/UI9D. 사람 자산 결정 후.
4. **신규 Mock 필요(라운드 이벤트)** — UI9C. 사람 Mock 결정 후.
5. **분석 데이터 정책** — Phase 5 기준 통계 의존. 그 전까지 예시값 명시 유지.

## 안전하게 구현 가능한 항목

- 배포 버전 표시: 기존 `frontend/package.json` version과 UI build label만 사용하면
  신규 Mock, 자산, 타입, 패키지 없이 구현 가능하다.
- 최근 경기 리스트의 승패 강조, 지표 압축, 헤더 KPI 재배치처럼 이미 화면에 있는
  데이터의 위치·밀도만 조정하는 변경은 별도 데이터 결정 없이 가능하다.
- 스코어보드의 팀 구분 헤더, 자기 행 하이라이트 강화, 기존 컬럼 재정렬은 기존
  경기 상세 데이터로 가능하다. 단, 새 컬럼(econ 등)은 만들지 않는다.

## 새 데이터 또는 자산이 필요한 항목

- 요원 placeholder 제거: 누락된 요원 이미지와 출처/라이선스 결정이 필요하다.
- 역할군 아이콘과 무기 Head/Body/Legs 분포: 현재 자산·Mock 필드가 없으므로 별도
  사람 결정이 필요하다.
- 라운드 첫 킬, 스파이크 설치/해제, 클러치, 멀티킬: `MatchRound`에 이벤트 필드가
  없으므로 신규 Mock/schema 결정 전에는 표시하지 않는다.
- 마지막 갱신 시각: 신뢰 가능한 timestamp 출처가 없으면 신규 Mock으로 간주한다.

## 사람/GPT가 결정할 항목

- 레퍼런스 유사도 허용 한계(정보 구조 참고 vs 시각 유사) 최종 기준.
- "마지막 갱신 시각" 표기를 위한 timestamp 출처(기존 데이터 vs 신규 Mock — Mock이면
  PENDING-DECISION).
- 배포 버전 문자열 출처(`package.json` version만 / + 빌드 시각 / + git SHA).
- 위 "작업 순서 재정렬 후보"를 확정할지, 조정할지.
