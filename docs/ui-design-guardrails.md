# UI Design Guardrails — Tracker.gg / OP.GG 참고 기준

이 문서는 전적 사이트(Tracker.gg / valorant.op.gg)를 참고해 GameProbe UI를
개선할 때 지켜야 하는 **경계 조건**을 정의한다. `ui-reference-audit.md`의 비교
결과를 실제 작업으로 옮길 때 이 가드레일을 우선 적용한다.

이 문서는 계획·검토용이며 제품 코드가 아니다.

Tracker.gg / OP.GG는 **참고 레퍼런스**일 뿐이며, GameProbe가 그대로 복제할
템플릿이 아니다. 이후 UI Task는 이 문서와 `ui-reference-audit.md`를 함께 확인한
뒤, 기존 GameProbe 디자인 언어 안에서 필요한 정보 구조만 재해석한다.

## 1. 가져올 것 (정보 구조·읽기 흐름)

- **정보 위계와 배치 원칙**: 핵심 KPI를 상단에 요약하고, 상세는 펼침/하위 탭으로
  내리는 읽기 흐름.
- **승패·자기 행 같은 핵심 신호의 시각 강조 방식**(컬러 바·하이라이트 위치).
- **카드/행의 정보 항목 구성**(예: 모스트 요원에 게임수·승률·KD 병기).
- **팀 구분·정렬·필터 같은 구조적 인터랙션 패턴**.
- **푸터/배지의 버전·기준 정보 표기 관습**.

## 2. 가져오지 않을 것

- 색상 팔레트·타이포그래피·아이콘·배지 **그래픽의 직접 모사**.
- 특정 사이트의 **고유 레이아웃 픽셀 단위 복제**.
- **광고 슬롯·제휴 링크·외부 위젯** 등 GameProbe 범위 밖 요소.
- 데이터가 뒷받침되지 않는 **장식용 패널·가짜 그래프**.
- 레퍼런스의 **브랜드 자산**(로고·마스코트·고유 일러스트).

## 3. 표절/복제처럼 보이지 않기 위한 기준

- 레퍼런스에서 가져오는 것은 **"무엇을 어디에 보여주는가"(정보 구조)**까지로
  한정하고, **"어떻게 보이는가"(시각 디자인)**는 GameProbe 자체 디자인 언어로
  재해석한다.
- 화면을 나란히 놓았을 때 **레퍼런스의 스크린샷으로 오인되지 않아야** 한다.
- 색·간격·폰트·컴포넌트 스타일은 기존 GameProbe `globals.css` 디자인 토큰을
  따른다. 레퍼런스의 수치를 그대로 옮기지 않는다.
- 문구·라벨은 직역 복사하지 않고 제품 톤에 맞게 작성한다.

## 4. 데이터가 없는 UI를 만들지 않는 기준

- **현재 Mock/타입에 존재하는 필드만** 화면에 표시한다.
- 표시하려는 지표가 데이터에 없으면, UI를 먼저 만들지 않는다. 먼저 데이터/Mock
  확장을 **별도 Task + 사람 결정**으로 분리한다.
- placeholder는 "데이터 없음"임이 드러나게 표시하고(예: `—`, "표본 없음"),
  실제 값처럼 보이는 더미 수치를 채우지 않는다.
- 분석/비교 문구는 **기준 통계 표본이 확보되기 전(Phase 5)**까지 단정하지 않고,
  예시값임을 명시한다(현 분석 탭 Mock Preview 방식 유지).

## 5. 외부 자산/Mock 추가가 필요한 경우의 Stop Condition

다음 중 하나라도 필요해지면 **그 자리에서 작업을 멈추고 사람 결정을 요청**한다.
임의로 진행하지 않는다.

- 신규 **외부 이미지/아이콘 자산** 다운로드·추가(요원 PNG, 역할 아이콘 등).
- 신규 **Mock 데이터/필드** 생성(라운드 첫 킬·스파이크·클러치 이벤트, 무기
  Head/Body/Legs, 갱신 timestamp 등).
- 신규 **타입 필드**·데이터 모델 변경.
- 신규 **npm 패키지**·런타임 외부 의존성(CDN·외부 API 호출 포함).
- 자산 **출처/라이선스** 확인이 필요한 경우.

> Stop 시: 무엇이 왜 필요한지, 대안(보류/placeholder 유지)을 함께 보고하고
> 사람 승인 전까지 해당 부분을 구현하지 않는다. (UI9B/UI9C/UI9D가 이 조건에
> 해당한다.)

## 6. 적용 순서

1. `ui-reference-audit.md`에서 영역별 "가져올 것/가져오지 않을 것" 확인.
2. 본 가드레일 4·5장으로 데이터/자산 충족 여부 판정.
3. 데이터/자산이 이미 있으면 진행, 없으면 Stop → 사람 결정 Task로 분리.
4. 표절 기준(3장)으로 시각 결과 자체 점검.
