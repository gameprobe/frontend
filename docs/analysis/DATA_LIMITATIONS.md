# DATA_LIMITATIONS.md - 데이터 제한사항

## 문서 목적

분석 시스템이 Riot 공식 API만을 데이터 소스로 사용할 때의 제한사항을
정리한다. `SCORING_RULES.md`와 `FEEDBACK_POLICY.md`의 "추측 금지" 원칙이 어떤
데이터 가용성 제약에서 비롯되는지 명시한다.

> 이 문서의 "확인 필요" 항목은 실제 Riot 공식 API 문서/응답을 검토하지 않은
> 상태의 가정이다. **API 필드가 존재한다고 단정하지 않는다.**

## 분류 기준

- **확인 필요 (가정)**: 일반적으로 알려진 VALORANT 경기 데이터 항목이지만,
  이 프로젝트에서 실제 API 응답을 통해 필드 존재 여부를 검증하지 않은 항목.
- **제한사항 (확정)**: API 필드 존재 여부와 무관하게, 공식 API의 성격상
  근본적으로 제공될 수 없는 정보.

## 확인 필요 (가정) — 검증 대상

| 항목 | 분석에서의 용도 | 비고 |
|------|------------------|------|
| 킬/데스 발생 위치 좌표 | zone 기반 분석(`SCORING_RULES.md`) | 좌표 체계와 맵 좌표 변환 방법도 함께 검증 필요 |
| 라운드 내 이벤트 발생 시각 | 라운드 단계별(초반/중반/후반) 분석 | |
| 능력(유틸리티) 사용 이벤트(종류/시점/대상) | Cypher 유틸리티 분석 | 사용 "위치"까지 포함되는지 별도 검증 |
| 플레이어 랭크/티어 조회 (MMR API) | 랭커 명단(`ranker_roster`) 수집 | 리전별 엔드포인트/권한 확인 필요 |
| 경제 정보(라운드별 크레딧/장비) | 추가 분석 항목 후보(MVP 필수 아님) | |
| 전투 통계(kills/deaths/assists, ACS) | `combat_stats` 비교(`SCORING_RULES.md`, `DATA_MODEL.md`) | TASK-006/TASK-010 Mock 데이터에는 필드가 존재하나, 실제 Riot API 응답 필드 존재 여부는 미검증 |
| 라운드 승패 결과 | 라운드 단위 비교(`SCORING_RULES.md`) | Mock 데이터에는 존재하나, 실제 Riot API 응답 필드 존재 여부는 미검증 |
| 스파이크 설치/해체 상태(`spike_state`) | `benchmark_stats` 식별 조건 후보(`DATA_MODEL.md`) | 라운드 단계별 분석을 위한 식별 조건 후보 — 실제 API 필드 존재 여부 미검증 |

이 항목들은 TASK-014(API Adapter 인터페이스, DONE)의 현재 인터페이스
(`getMatchDetail` 등)에 아직 반영되지 않았다. Phase 5 진행 시 실제 Riot
Match-V1 API 응답을 확인한 뒤, 어댑터 반환 타입 확장 여부를 별도로 결정한다.

## 제한사항 (확정) — 공식 API로 얻을 수 없음

| 항목 | 이유 |
|------|------|
| 사운드 인지 여부(발소리 등을 들었는지) | 클라이언트 오디오/인지 정보는 API로 제공되지 않음 |
| 실제 시야/인지 정보(화면에 적이 보였는지) | 시야각·렌더링 정보는 API에 없음. 위치 좌표만으로 "보였다"를 단정할 수 없음 |
| 플레이어 의도 | 의도는 관측 불가능한 정신 상태 |
| 음성 채팅/팀 커뮤니케이션 내용 | API 범위 밖, 별도 동의·수집 체계 필요(범위 밖) |
| 입력 장치/하드웨어/설정 정보 | API 범위 밖 |
| 경기 외 연습/훈련 데이터 | API는 경기(매치) 데이터만 제공 |

## 분석 설계에 미치는 영향

- "확인 필요" 항목(위치/시각/유틸리티/경제 정보 등)이 실제로 존재하지 않는
  것으로 확인되면, `SCORING_RULES.md`의 zone 기반 분석 항목은 **"B 사이트
  수비 라운드" 단위의 비-위치 통계**로 축소될 수 있다(`SCORING_RULES.md`
  "규칙이 평가하는 항목" 표 참고).
- **combat_stats(kills/deaths/assists/ACS)와 라운드 승패 결과도 실제 Riot
  API 필드 존재 여부가 검증되기 전까지는 "확인 필요"로 취급한다.** "기본
  항목이므로 검증이 필요 없다"는 예외는 두지 않는다. 이 항목이 검증되지
  않으면 해당 지표를 사용하는 분석 항목은 활성화하지 않으며, 결과에서
  `INSUFFICIENT_DATA`로 표시하거나 해당 비교 항목 자체를 비활성 처리한다
  (`SCORING_RULES.md`, `DATA_MODEL.md` 참고).
- "제한사항(확정)" 항목은 규칙·AI 출력 어디에도 포함되지 않는다
  (`SCORING_RULES.md` "추측 금지 항목", `FEEDBACK_POLICY.md`와 연결).

## 검증 계획

- Phase 5 착수 전, 실제 Riot Match-V1(및 관련) API 응답 샘플을 확보해 "확인
  필요" 항목의 필드 존재 여부를 확인한다.
- 검증 결과는 이 문서를 갱신해 "확인됨/미제공"으로 재분류한다.
- 어댑터(TASK-014 `RiotApiAdapter`) 반환 타입에 새 필드가 필요하면 별도
  Task로 분리한다(이 문서는 Task를 생성하지 않음).

## 확정 사항 vs 검증 필요 사항

**확정**

- 사운드/시선/의도/음성/하드웨어/연습 데이터는 공식 API로 얻을 수 없음 —
  분석·AI 출력에서 영구 제외
- 데이터 소스는 Riot 공식 API로 한정(비공식 API/크롤링 미사용)

**검증 필요**

- 위치 좌표, 이벤트 시각, 유틸리티 사용 상세, MMR/티어 조회 API의 실제 필드
  존재 여부
- combat_stats(kills/deaths/assists/ACS), 라운드 승패 결과의 실제 Riot API
  필드 존재 여부
- 스파이크 설치/해체 상태(`spike_state`) 필드 존재 여부
